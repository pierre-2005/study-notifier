## Additional integration fixes

- `app/task_service.py` centralizes status transitions across board, inspector, full edit, inline completion and batch operations. Prerequisites cannot be bypassed through another endpoint. Recurring completion creates one successor even after reopening/completing again. Parent validation covers the complete moved subtree, same-project membership, depth and cycles. Corrupt legacy cycles render safely instead of disappearing or recursing forever.
- `app/lifeos.py` renders nested context in Tasks, Today and project views, including paginated ancestors and correct descendant totals. Shared-project viewers see read-only controls. Calendar dates use the viewing user's timezone and timed external cache values; page rendering does not call providers.
- `app/reminders.py` handles owned tasks, projects, local/external events, legacy assignments/exams/labs, work tasks/follow-ups, legacy unpaid bills, personal note-review dates and focus ends. It uses selected modules, explicit mutes, subtype fallback, timezone/date-only time, quiet hours, deadline-aware coalescing and retry leases. Only active, approved and appropriately verified accounts' own devices are eligible. The original finance/academic source owner is explicitly bound, not inferred from user count.
- `app/auth_delivery.py`, `app/account_security.py` and `app/auth.py` implement encrypted queued verification/recovery mail, one-use expiring HMAC reset codes, rate/attempt limits and session revocation. Password changes invalidate outstanding reset tokens/codes and queued recovery mail. Administrators cannot redirect recovery or set a password known to them. Existing account role/capability data and bootstrap password hashes are preserved.
- `app/course_import.py`, `outline_parse.py`, `outline_ai.py` and related templates/JS add private PDF/DOCX/PNG/JPG/TXT extraction with OCR, bounded parsing, editable source review, unknown-date handling and transactional duplicate-safe task creation. Optional AI uses explicit per-upload consent and a strict schema, carries no tools/calendar credentials and starts with all suggestions unselected. Local extraction remains available without API credentials. Imported assessment pages display current task titles/status/dates rather than a second editable task copy.
- `app/legacy_access.py` and `consolidation.py` bind historical global records to their existing bootstrap owner. Other administrators do not gain access to another user's legacy private data. Member Finance access has not been expanded. Original finance budgets and initialization avoid duplicate seeds on older schemas without unique constraints.
- `app/bootstrap.py`, `backup.py`, `db.py` and `scripts/rehearse_v37.py` share additive initialization, add a checked online pre-upgrade backup, close SQLite context connections and support a read-only-source migration/restoration rehearsal. Existing secrets, volume, ports and callback routes are preserved.
- `workspace37.css`, `task-inspector.js`, base/components and public privacy disclosures establish the shared interface, contextual task editing, readable controls, mobile focus behavior and clear import/email data handling. Relevant tests were updated for deliberate UI wording and the owner-delivered recovery contract. Browser selection is portable rather than hardcoded to `/usr/bin/chromium`.
- Timezone data is pinned to `tzdata==2026.5` (IANA 2026e), and Docker/CI select the packaged rules with `PYTHONTZPATH=""`. CI exposed a stale local Edmonton database and an incorrect fixed-UTC test assumption. The test now derives its clock from the selected zone; separate tests cover current Alberta rules, historical DST and unchanged explicit UTC timestamps. No stored timestamps or timezone preference names are rewritten.
- Docker adds OCR tools. Compose passes optional scheduler/AI settings with AI disabled by default. The publishing workflow keeps its normal main trigger and AMD64/ARM64 targets and uses release tag `v3.7.0`. PR validation now builds and starts AMD64 and ARM64 images without publishing; main publication waits for the same complete validation workflow.

## Retained product boundaries

There is one task state across board, list, table, Today and Calendar. Course records retain assessment provenance/weights while linking actual tasks. Legacy academic records and Finance remain in their existing systems. The user can intentionally show a record through more than one view; this does not create another task.

The importer currently extracts assessments and deadlines, not arbitrary lecture recurrences, office hours, LMS content or a complete executable course model. Dates, OCR and AI output require review. New imported deadlines appear in MLO Calendar; they are not silently bulk-written to Google/Microsoft. Existing explicit calendar destination/create/edit flows remain available. The owner subsequently requested the shared redesign and calendar-aware automatic study planner in this release. A complete editor/information-architecture replacement and generalized graph links remain future v4 work. No feature parity or performance multiplier relative to competitors is claimed.

## Final release continuation

- `app/study_planner.py` adds private availability, task estimates minus logged focus, imported exact deadlines, prerequisite/leaf-task checks, cached calendar/class conflicts, quiet-free availability windows, session breaks and daily limits. Preview is private, expires in 15 minutes and is tied to an input snapshot. Apply, pin, clear and guarded 24-hour undo are transactional. Existing manual/pinned/started sessions are preserved. Identical task/time slots retain event IDs so replanning or renaming does not duplicate reminder delivery history. Automatic planning is off until explicitly enabled; it checks at most every 15 minutes per eligible account. Incomplete/failed/stale calendar connections block new plans until refreshed.
- `app/calendar_links.py` additively retains provider event ends, busy/free and all-day flags. Google and Microsoft pagination is followed with bounded results; Graph UTC responses get explicit suffixes. Invalid pagination targets cannot receive bearer credentials. `calendar_recurrence.py` expands bounded daily/weekly/monthly/yearly ICS rules, RDATE/EXDATE, moved exceptions and cancellations. Oversized or unsupported feeds fail without deleting the previous cache. Local and external event forms now use the account's timezone and reject missing/ambiguous DST clocks.
- `app/agenda.py` displays today's owned local/external events and the original owner's classes without remote requests. Today/task filters use the account's local date. Study and Work render the shared nested tree. Private imported assessments appear in Study deadlines, course progress uses actual task completion, and course projects are not duplicated in the Study projects card.
- `product37.css`, `icons.html`, base and Study/Calendar/Settings templates provide the final shared shell and planner interface. Calendar events are available to members from New; mobile controls avoid clipped time fields and retain 44-pixel targets. Public operator-variable placeholders were removed; useful setup details remain in operator documentation. Connected calendars always offer a manual refresh for recovery.
- `auth_delivery.py` discards superseded queued reset codes before queuing the newest one. Existing verification and administrator approval policies remain in force.
- `tests_v37_planner.py` adds 12 acceptance tests; `tests_v37_calendar_time.py` adds seven calendar precision/paging/recurrence tests. `tests_v37_upgrade.py` uses a synthetic fixture generated by actual pre-v3.7 main, preserving 49 original tables, permissions, encrypted calendar data, finance and attachment content through backup/migration/restore.
- The final browser flow covers 17 routes at four widths plus planner preview/apply/undo/pin/clear. Shared-shell, plan preview and mobile states are audited across all palettes. The old dashboard test now expects its deliberate default name, Today; custom names/order still persist.
- The main publish workflow reuses the entire PR regression and AMD64/ARM64 build/start workflow, so publication cannot bypass the release checks. OCR tools and timezone pin remain in both images. Volume, path, ports, credentials and callbacks remain unchanged.
