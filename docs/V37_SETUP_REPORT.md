# MLO v3.7 setup report

Prepared October 23, 2026. The initial release was merged in [PR #1](https://github.com/pierre-2005/study-notifier/pull/1); v3.7.1 adds the separately tested all-day calendar correction. Version: **3.7.1**. The owner handles Portainer redeployment after the existing GitHub Actions publication completes. No production database, Portainer stack, DNS account, mail account or live OAuth connection was accessed during development.

## What is implemented

All-day calendar dates now stay consistent across Calendar, Today and reminders, including older cache rows. The shared interface has new typography, spacing, line icons, form controls and responsive layouts. Tasks share one state across nested lists, tables, boards, Today and Calendar. Contextual task editing, mouse/touch drag, keyboard moves, source review, live appearance and per-account preferences are connected to the real records. Study shows imported course progress and deadlines. Today includes a private calendar agenda. Obsolete Settings navigation toggles, repeated settings actions and nonessential introductory/operator copy were removed.

Personal reminders cover the existing task, project, event, academic assessment, work/follow-up, bill, note-review and focus sources through each user's own notification devices. Finance and historical academic/job data remain private to their original installation owner. This is not a new per-user Finance migration.

Course outlines accept PDF, DOCX, TXT, PNG and JPG, with OCR for scans. Local extraction works immediately. Review/edit dates, assessment types, weights, selected rows and evidence before adding real tasks. Unknown dates stay unscheduled; repeated imports do not create another copy. Optional AI is described below.

Study planner uses your availability, task estimates, logged focus time, deadlines and existing local/connected calendar commitments. Preview, Apply, Pin, Clear and Undo work with private MLO calendar events. Automatic replanning requires explicit opt-in. Existing provider create/edit/delete flows remain available; the planner does not silently bulk-write Google or Outlook events.

## Email: verification and password recovery

The code is complete; an actual SMTP sender and DNS verification are operator setup. Follow the detailed [email walkthrough](V37_EMAIL_SETUP.md). In the existing stack environment set:

| Variable | Required value |
| --- | --- |
| `MLO_PUBLIC_URL` | `https://organizer.overvault.ca` |
| `MLO_SMTP_HOST` | Your provider's SMTP submission host |
| `MLO_SMTP_PORT` | Usually `587` with STARTTLS, or `465` with implicit TLS |
| `MLO_SMTP_STARTTLS` | `true` for port 587 |
| `MLO_SMTP_USER` | Your SMTP username |
| `MLO_SMTP_PASSWORD` | SMTP credential, entered privately in Portainer |
| `MLO_SMTP_FROM` | Verified sender, for example `My Life Organized <no-reply@account.overvault.ca>` |
| `MLO_LEGAL_CONTACT_EMAIL` | A real monitored support/privacy address |
| `COOKIE_SECURE` | `true` with the existing HTTPS domain |

Verify the sender domain using the provider's exact SPF/DKIM records, review DMARC alignment and disable account-email tracking. Do not replace unrelated DNS/mail records. Keep the current session and calendar encryption keys.

Users create their own accounts at `/signup`, receive a verification link, confirm it, and wait for administrator approval in **Users**. Both verification and approval are required for new accounts; approval has deliberately not been bypassed. Existing accounts keep their previous sign-in eligibility. Existing users can verify a recovery address through **Settings → Account security**.

Forgot password sends a six-digit, one-use code to a verified address. It expires after ten minutes and permits five attempts. Success invalidates old sessions. Mail is encrypted while queued, attempted immediately and retried by the scheduler until expiry. A newly issued code supersedes older queued codes. Administrators cannot choose a member's password or redirect recovery to their own mailbox.

Before inviting users, use two controlled mailboxes to test signup, inbox/spam delivery, verification, approval, login, resend, expired codes, successful reset, rejected replay and old-session invalidation. Provider acceptance and mocked regression tests do not establish inbox deliverability. Accounts can be created without configured SMTP, but their verification mail cannot arrive until a sender is configured and a valid link is resent.

## Optional AI course extraction

Local extraction and OCR need no AI account. To enable the optional upload checkbox, set all three:

| Variable | Value |
| --- | --- |
| `MLO_OUTLINE_AI_ENABLED` | `true` |
| `OPENAI_API_KEY` | A private project API key with available API access/billing |
| `MLO_OUTLINE_AI_MODEL` | A model available to your project that supports Responses API structured JSON schema output |

Select AI for an individual upload only when you want it. The request sends extracted outline text and the chosen year, with `store=false`, a strict schema and no tools. It does not send calendar credentials, other workspace content or the raw upload. AI suggestions start unselected and still require review against the source. Configure limits/billing in the provider account and test a known outline in staging. Live-model extraction quality was not tested with a paid key here. If configuration or a request fails, use local extraction. See [OpenAI Responses documentation](https://platform.openai.com/docs/api-reference/responses) for compatible account/model setup.

## Calendar and automatic study planning

Retain current Google/Microsoft client IDs, client secrets, encryption key and registered callback:

`https://organizer.overvault.ca/life/calendars/callback`

Keep `MLO_CALENDAR_AUTO_SYNC=true`, the existing `MLO_CALENDAR_SYNC_MINUTES` (default 10) and a modest batch size (default 3) for the Pi. Existing connections should refresh with their stored tokens. Use **Connected calendars → Refresh events** to inspect errors and populate new end/busy metadata. Reauthorize only a connection that actually needs it. Calendar pages use the cache rather than performing provider HTTP requests during ordinary loads.

Google/Microsoft events retain end times and busy/free flags; both pagination paths are handled. ICS subscriptions expand daily/weekly/monthly/yearly rules and exceptions within a bounded window. Subdaily recurrence or oversized feeds are refused with an error while the old cache is retained. ICS remains read-only. All-day or missing-duration data is treated conservatively. A connection with no successful sync, a failure, or a success older than 24 hours blocks a new study plan until refreshed.

Open **Study → Plan study time**. Set the timezone in personal preferences, then set weekly availability, session length, breaks, daily limit and task estimates. Date-only tasks use your chosen reminder/day time as the deadline; imported exact times are honored until their date changes. Tasks without a date or with open prerequisites are shown under Needs attention. Only owned open Study leaf tasks are scheduled; no tasks or commitments from another user's private workspace are used.

Preview first, then Apply. Pin a session or edit it to protect it. Undo is available for 24 hours only while tasks/calendars/settings still match the applied plan, so it cannot overwrite later work. Clear removes only future, unmodified, unpinned generated sessions and pauses automatic planning. **Keep my plan up to date** is off by default; saving it enables checks at most every 15 minutes per eligible user. Keep `MLO_SCHEDULER_ENABLED=true` for automatic planning, reminders and mail retries.

Before wider use, test one controlled Google and one Outlook account end to end: connection, refresh, event create/edit/delete, disconnect and conflict avoidance. Preserve existing provider registrations. Actual live credentials were unavailable during development.
